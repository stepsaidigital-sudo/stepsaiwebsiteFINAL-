## 1. Real bugs (fix these)

### 🔴 case-studies.html — invisible final-CTA headline (contrast failure)
The final CTA (`#final-cta`, `section section--base final-cta`) uses `section--base` (light bg, `rgb(250,251,252)`) instead of `section--dark` like every other page's final-cta. But `.final-cta-headline` has a hardcoded near-white text color (`rgb(248,250,252)`) meant for dark sections — contrast ratio ~1:1, headline "Want to be the next real one on this page?" is essentially invisible. Confirmed by comparing computed styles against channel-instagram/standalone/website/whatsapp, founders-note, and integrations — all 6 correctly use `section--dark final-cta`; case-studies.html is the outlier. Secondary: the "Start free trial" button is a plain white box on a near-identical near-white background — looks unstyled, very low affordance.
**Fix:** add `section--dark` to that section's classes (matching every other page), or scope a `.final-cta-headline` color override to `.section--base`.

### 🔴 channel-standalone.html + channel-website.html — invisible hero widget text (contrast failure)
The hero "browser mock" widget preview (`.widget-launcher`) has white text on a near-white background in multiple spots: `.widget-launcher-head` (the "Nyra Store" title), `.widget-launcher-bubble` ("Hi! Ask me anything about Nyra Store."), and `.widget-lead-row` ("Powered by StepsAI") — all render essentially invisible; confirmed via computed styles AND screenshot on both pages (only one span with an explicit gray override stays legible). Screenshots look like empty skeleton bars where real copy should be.
**Fix:** give `.widget-launcher-head`, `.widget-launcher-bubble`, and `.widget-lead-row` real text colors that contrast against their actual (light) backgrounds.

### 🟠 Broken footer "Integrations" link — 4 pages
`channel-instagram.html`, `channel-standalone.html`, `channel-website.html`, `channel-whatsapp.html` all have a footer Product-column link `<a href="agents.html">Integrations</a>` — should be `integrations.html` (which exists as its own real page). Confirmed wrong by cross-checking: these same 4 pages' own top-nav mega-menu correctly links "Integrations" → `integrations.html`, so each page's footer contradicts its own header. Identical copy-paste bug across all 4 files.
**Fix:** change the href to `integrations.html` in all 4 files.

### 🟡 channel-standalone.html — orphaned CSS classes in hero mock
`.url-bar-pill` and `.url-bar-row` (the fake address-bar showing "stepsai.link/nyra-store" in the hero browser-mock) have zero matching CSS rule across all 10 stylesheets — renders as plain unstyled text instead of a pill/address-bar. Same hero component that already has the white-on-white widget-launcher text bug above — this mockup needs a pass.

### 🟡 case-studies.html — placeholder-sounding copy live in production
The trust-strip below the hero reads "A customer-logo strip goes here once we can name names. For now, here's what's actually confirmed." — reads as an internal dev note rather than finished copy, even if intentional/honest.

### 🔴 workflows.html — dead interactive tabs (functional)
The "Five jobs, one automation engine" section has 5 tabs (`.wflow-tab`) wired by `wireTabs('.wflow-tab','.wflow-panel')`, which only exists in **`agents.js`**. workflows.html loads `nav.js` + `industries.js` but **never loads `agents.js`**. Result: only the default "Recover carts" tab ever shows content — Follow up leads / Remind customers / Re-engage / Broadcast & promote are all dead clicks.
**Fix:** add `agents.js` to workflows.html's script tags (check for ID/selector collisions with industries.js first).

### 🔴 `faq-chevron` / `.faq-chev` class typo — 4 pages, chevrons never animate
Confirmed via direct grep — **`partner.html`, `pricing.html`, `product.html`, `solutions.html`** all use `class="faq-chevron"` on the FAQ chevron SVG, but `styles.css` only defines `.faq-chev` (the rotate-on-open + recolor rules target that class). Accordions still open/close fine (JS-driven), the icon just never rotates or recolors. `workflows.html`'s own FAQ correctly uses `faq-chev` — good reference.
**Fix:** rename `faq-chevron` → `faq-chev` in all 4 files.

## 2. Site-wide architecture inconsistency (needs a decision, not just a fix)

The site currently runs **three different primary-nav layouts** and **three different footer layouts**, depending on which redesign pass a page last went through:

| Group | Pages | Nav shape | Footer |
|---|---|---|---|
| Homepage | `index.html` | Mega-menu; standalone Industries dropdown; Solutions = Partner+role only | `footer--9` (newsletter card, blobs, "Roles" column) — unique |
| Blog family | `blog.html` + 4 `blog-*.html` | Mega-menu; Solutions merges industry+role; adds standalone "Partner" link | `footer-inner--5col` (5 links per column) |
| Career/Contact | `career.html`, `contact.html` | **No mega-menu** — flat "Product"/"Solutions" links, visibly stripped-down header | `footer-inner--5col` class, but content silently diverged (see above) |
| Industries group | `industries.html` + 6 industry-*.html, `industry-saas.html`, `partner.html`, agent/role pages (lead/meetings/sales/support-agent, role-*.html, solutions.html, workflows.html) | Older/simpler nav template, pre-homepage-redesign | Same older template |

None of this is a "bug" per se — it's the natural result of the homepage getting rebuilt independently in the most recent sessions while the other ~35 pages didn't. But it means the site currently reads as 3 different products depending which page you land on. **Also:** mobile nav on the blog family is missing "Founder's Note" and "Careers" links that exist on desktop (reachable via footer only).

**Recommendation:** pick the homepage's current nav/footer as canonical (it's the newest, most complete version) and propagate it site-wide in one pass — this is the single highest-leverage fix on the list, but also the riskiest (touches every page), so it should be done centrally rather than piecemeal.
