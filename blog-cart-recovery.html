The problem with manual follow-up

Someone adds a product to their cart, gets distracted, and leaves. If a human is meant to notice and follow up, that follow-up happens whenever someone next checks the dashboard — an hour later, the next morning, or not at all. By then the moment that made them want it has usually passed.

A blanket "10% off everything" email blast recovers some of that, but it trains customers to wait for a discount instead of buying when they meant to.

The workflow, node by node

The diagram above is a real, live example from Workflows — not a diagram drawn for this post. It's a five-node chain: a trigger, a wait, a check, and two actions. Nothing about it needs a developer to set up.

Step 1: the trigger and the wait

The workflow starts the moment a cart is abandoned — in this example, a ₹2,400 cart. It doesn't message immediately. It waits 30 minutes first, because a message that arrives while someone's still mid-checkout reads as pushy, not helpful.

The wait is configurable, not fixed

30 minutes is what's set in this example. Some stores wait 15 minutes, others wait a few hours — it depends on how considered the purchase is.

Step 2: the check that matters

Before sending anything, the workflow checks one thing: did the order actually get placed in the meantime? If it did, the workflow just stops — nobody gets a "did you forget something?" message for a purchase they already completed. That single connector node is what separates a workflow from a dumb timed blast.

Step 3: the message, then the handoff

Only if the cart is still genuinely abandoned does the WhatsApp message go out. And it isn't a one-way blast — the same agent that sent it stays in the conversation, answers whatever comes back ("is this still in stock?", "can I get it in a different size?"), and shares the checkout link directly in the chat.

Why this works better than a discount blast

A scheduled email blast treats every abandoned cart the same. This workflow treats each one as a conversation that's still open — it waits for the right moment, checks whether it's even still relevant, and then picks the conversation back up rather than starting a new one. That's the difference between "recovering revenue" and "training customers to expect a discount."

The same trigger→wait→check→action shape runs the other four workflows in the platform too — following up on a quiet lead, reminding a customer of an appointment, or sending a broadcast. If you want to see how one inbox handles everything these workflows generate, that's the previous post.
